# ISP TLM Line-Granular Architecture Refactor

## Outcome

Refactor `components/isp_tlm/systemc` into a causal, line-granular internal ISP architecture model.
The delivered model retains one `SC_THREAD` per logical ISP block, exchanges slot-backed line tokens between blocks, represents spatial history in stage-local SRAM, and records timing only at meaningful events.
The full-frame C++ pipeline remains the untimed functional oracle used by tests.

Done means the line model produces the same final bytes as the oracle for supported configurations, cannot deadlock because a frame is larger than an inter-stage FIFO, exposes latency separately from initiation interval, and reports internal bottleneck candidates without modeling DMA, DRAM, or bus contention.

<Callout id="scope-decision" tone="decision">

The exploration boundary is the ISP pipeline itself.
An ideal testbench source supplies RAW lines whenever ingress credit exists, and an ideal sink consumes YUV output immediately.
DMA, DRAM, bus arbitration, configuration-file loading time, and external backpressure are outside the timed model.

</Callout>

## Scope and non-goals

### Included

1. Line-granular channels across all 18 logical stages, including the input normalizer.
2. Per-link preallocated storage, slot ownership, ready queues, and credits.
3. Stage-local line SRAM for DPC, BNR, demosaic, sharpen, and 2DNR.
4. Logical in-flight line scheduling with independent latency and initiation interval.
5. Next-frame AWB and AEC feedback with an explicit frame-start barrier.
6. Scale and YUV420 rate changes, including plane-aware output placement.
7. Event-duration metrics and local bottleneck-candidate reporting.
8. Differential functional verification against `isp_pipeline::run()`.
9. Real pipeline sweeps over coherent architecture candidates rather than mock formulas.

### Excluded

1. Read or write DMA processes.
2. `b_transport`, `nb_transport`, DRAM timing, and bus arbitration.
3. LUT or scalar configuration transfer time.
4. RTL-calibrated latency claims before RTL or HLS evidence exists.
5. Proven causal bottleneck attribution from local counters alone.
6. Power-model calibration.

## Current evidence and target delta

| Current behavior | Target behavior |
| --- | --- |
| Pixel-typed `sc_fifo` links with one thread per block | Slot-backed line channels with one thread per block |
| Point blocks wait per pixel in timed mode | Blocks wake for line arrival, issue, completion, credit, feedback, or reset |
| Spatial blocks wait for a complete frame | Spatial blocks ingest lines into bounded stage-local SRAM and emit rows when halos are ready |
| DPC requires `width * height` tokens to coexist in a FIFO whose top-level depth is 1024 | DPC consumes each input line immediately and retains only the rows required by its 5x5 neighborhood |
| Pipeline depth and throughput are conflated by serial waits | `compute_latency`, line issue interval, and maximum in-flight lines remain separate |
| Architecture sweep uses `run_mock_simulation()` | Sweep runner constructs and executes the actual line pipeline |
| Lowest utilization is labeled the bottleneck | Reports rank internal bottleneck candidates from local issue, wait, occupancy, and rate evidence |

<Callout id="deadlock-evidence" tone="risk">

`sc_dpc::process_stream()` waits until `fifo_in->num_available()` reaches the full frame size before consuming any token.
The top-level creates that boundary with depth 1024.
Any enabled DPC frame larger than 1024 pixels can therefore deadlock before functional work begins.
The line cutover must eliminate every whole-frame availability predicate before the full pipeline is considered operational.

</Callout>

### Ownership model

Each link owns a fixed number of line-sized slots.
A token carries metadata and a slot identifier, never an owning pointer or `std::vector`.
The producer reserves an unpublished slot, writes the functional result, schedules its completion time, and publishes the slot only when the result is ready and the boundary has credit.
The consumer reads the token, accesses a const view, ingests or processes the line, and releases the slot.

Spatial blocks copy an incoming line into their own stage-local SRAM and release the upstream slot after ingestion.
The stage-local SRAM remains distinct from inter-stage FIFO capacity so buffer-depth sweeps do not silently change halo storage.

## Ordered implementation plan

### 1. Establish deterministic baselines

Reuse `tb_pipeline`, `tb_arch_pipeline`, and `tb_d65_pipeline` before changing interfaces.
Capture current oracle output hashes, observed deadlock boundaries, host elapsed time, SystemC process wake counts where available, and current metric files.
Do not treat the existing mock sweep results as a baseline for architectural accuracy.

### 2. Add line ownership and event-runtime primitives

Add `line_channel.h`, `stage_runtime.h`, and `frame_feedback.h` without wiring them into the full pipeline.
Add focused contract tests for slot reuse, double-release rejection, bounded publication, completion ordering, simultaneous events, frame metadata, and reset.
Implement the channel so elaboration allocates every sample slot and the runtime path performs no heap allocation.

### 3. Convert block interfaces and pure line kernels

Convert all block headers to line input and output interfaces in one clean API cutover.
Implement point and LUT blocks first because they establish the common one-line-in and one-line-out path.
Implement spatial blocks next using stage-local SRAM and exact mirror or clamp border semantics from the golden kernels.
Implement AWB and AEC accumulation with end-of-frame commits.
Implement Scale and YUV420 last because they change row counts, widths, planes, and final output offsets.
Keep block-level tests executable throughout the migration; do not add permanent pixel-to-line compatibility adapters.

### 4. Cut over the top-level pipeline

Replace pixel FIFO allocation and binding in `sc_isp_pipeline::init_modules()` and `bind_channels()` with typed line channels.
Retain the current block order, configuration objects, LSC LUT ownership, metrics entry points, and golden accessors that remain meaningful.
Add the feedback latch to the top level and gate each frame snapshot before its first RAW line is accepted.
Use an ideal line source and sink in the testbench, not simulated DMA or timed external streams.

### 5. Replace per-cycle timing with event scheduling

Derive line issue intervals from width, pixels per cycle, and pixel II.
Schedule each produced line at `ready_at = issue_time + compute_latency` while allowing up to `max_in_flight_lines` logical records.
Wake a block only for input arrival, issue eligibility, completion, downstream credit, feedback readiness, reset, or end-of-frame flush.
Track issue-side and retire-side durations separately so active work and output blocking can coexist.

### 6. Make metrics and sweeps describe the real model

Replace lowest-utilization bottleneck labeling with candidate evidence based on achieved issue rate, input availability, output credit, local SRAM waits, in-flight occupancy, and neighboring link occupancy.
Label reports as bottleneck candidates because the selected local counters do not prove root cause.
Replace `run_mock_simulation()` in `tb_arch_sweep.cpp` with actual construction and execution of the line pipeline.
Sweep coherent block variants that bind latency, II, lanes, SRAM ports, and storage together, and retain `timing_source::assumed` until implementation evidence exists.

### 7. Verify the complete architectural contract

Run block-level differential tests before the full pipeline.
Run small deterministic frames covering odd widths, odd heights, minimum legal dimensions, disabled blocks, maximum configured windows, Scale up and down, and YUV420 plane placement.
Run at least one real RAW fixture through both the oracle and line pipeline and compare final bytes.
Demonstrate internal backpressure by constraining selected inter-stage depths while keeping the ideal source and sink unchanged.
Demonstrate that changing timing parameters alters timestamps and occupancies but never output bytes.
Compare scheduler activations and host elapsed time against the captured pixel-model baseline.

## Risks and controls

<Callout id="border-risk" tone="risk">

Chunk boundaries must never become image boundaries.
Every spatial stage must preserve the golden kernel's top, bottom, left, and right padding semantics and must flush its final output rows explicitly at end of frame.
Block differential tests must cover dimensions smaller than or equal to the active kernel diameter.

</Callout>

<Callout id="feedback-risk" tone="risk">

AEC is downstream of DG, so applying frame N feedback to DG for frame N+1 requires an ingress frame barrier until AEC commits.
This barrier is an intentional internal statistic cost and must appear in metrics as `FRAME_STATISTICS_BARRIER`, not as input bandwidth starvation.

</Callout>

<Callout id="rate-change-risk" tone="risk">

Scale and YUV420 break the one-input-line to one-output-line assumption.
Their APIs must permit zero or multiple scheduled output tokens per consumed row, and final output placement must use plane plus byte offset rather than FIFO arrival order.

</Callout>

<Callout id="timing-risk" tone="warning">

Without RTL or HLS, all cycle counts are architecture assumptions.
Reports may compare candidates and diagnose internal pressure, but they must not claim cycle-accurate hardware correlation until measured values replace assumed provenance.

</Callout>
