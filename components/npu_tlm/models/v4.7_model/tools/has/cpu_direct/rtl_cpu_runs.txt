# RTL runs of the CPU-direct programs of this directory: stored results (the RTL tree and its simulation are not part of this tree).
# Read by tools/has/verify_flows.py (flows CPU_*): for every run it computes the MD5 of the model program <test>/mmio.txt that this tree
# generates and says whether it is the program that was run on the RTL.
#
# Bench: tb_neo_top_cpu.sv around neo_top of neo_lite RTL revision 2, Verilator 5.052. The CPU writes the configuration port of neo_top
# (AXI-Lite: SAURIA, GVU and DMA blocks at the FPGA offsets), the data flow controller stays idle; at the end the bench compares the DRAM
# regions of the program ("K" lines) with the golden image of the model and prints "C1 RESULT". The model program is converted to the bench
# format (block addresses of the FPGA, DRAM base of the bench) without changing any value or the order of the accesses.
#
# Builds:
#   wc           neo_lite revision 2 with the corrected core word count (29 words; the RTL as delivered rounds to 92), two-port DRAM model
#                in the bench.
#   wc_hold      wc + a correction of the vector unit that holds the vbank2 write address between accesses in GEMM_FUSED (proposed to the
#                hardware team, enabled at run time); with the correction off the binary behaves as wc.
#   wc_hold_off  the wc_hold binary with the correction off: the vector unit as delivered.
#
# run <test> <build> mmio <MD5 of the model program> rtl_prog <MD5 of the converted program> | <C1 RESULT line> | <timeline in core cycles>
