# core_rtl -- model root for running the RTL-accurate core in a system wrapper

Point a system integration wrapper's model root at this directory instead of the repository root to run instruction
streams on the RTL-accurate core. Nothing else in the wrapper's build changes: the same files exist at the same paths.

| Model root | What runs |
|---|---|
| repository root | native top level: native core, functional decoder for the instruction registers |
| `core_rtl/` | same native behaviour, plus: instructions pushed after writing extension registers run on `HasNpuTop` (RTL-accurate core, HAS data flow, DMA, epilogue, vector unit) |

## Files

- `npu_top.h`: the drop-in top level (class `sauria::NpuTop`, same template parameters, constructor, ports,
  `attach_perf()`, `set_dram()` and `decoder_inst` as the native one). Host bus routing, counters and environment
  variables are described at the top of the file.
- Every other file: a one-line forwarding header to the file of the same path in the repository, generated by
  `python3 tools/has/make_core_rtl.py` (run it after adding a header include; `--check` reports missing ones).

## Using it

`docs/SW_INTEGRATION_GUIDE.md`, section 10: model root, the wrapper change for the DRAM window
(`tools/has/wrapper/npu_tlm_rich_window.patch`), the firmware sequence, the performance counters and the limits.
The reference firmware sequence is `tools/has/wrapper/test_npu_tlm_core_rtl.cpp`.
