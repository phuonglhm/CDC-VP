# Code Map

For a first run see `USER_GUIDE.md`.

The model is header-only C++17. Each hardware block is one or more `.h` files. Testbenches are `.cpp` files
that include the headers they need.

## 1. Top level

| Path | Content |
|---|---|
| `npu_top.h` | Native top level (dual lane) |
| `rtl_ref_npu_top.h` | RTL-ref core top level |
| `core_rtl/` | Model root for system wrappers: drop-in `npu_top.h` that runs extended instructions on `HasNpuTop`; every other file forwards to the repository (`core_rtl/README.md`) |
| `config_map.h`, `config_regs.h` | v4.5 register map and register file |
| `rtl_ref_config_map.h`, `rtl_ref_config_regs.h` | RTL-ref register map and register file |
| `sauria_types.h` | Common data types (`act_vector_t`, `psum_vector_t`, `host_data_t`, masks) and address constants |
| `sauria_targets.h`, `sauria_cfg_layout.h` | Target descriptions and configuration field layout |
| `npu_profile.h` | Runtime profile selection |
| `fp16.h` | Half-precision type |
| `debug.h` | Debug print switch (`SAURIA_DEBUG`) |
| `Makefile` | Build targets of the native model |

## 5. Data

The data package is carried in `data/` as a split archive with its checksum (`data/README.md`);
`tools/unpack_data.sh` extracts it to `sauria_npu_data/`, which is then used as `$FE_WORK`. The repository root
also holds `package_manifest.txt` (sha256 of every file), `.gitattributes` (no line-ending conversion) and
`.gitignore` (extracted data, build outputs).

Everything under `$FE_WORK`:

| Path | Produced by |
|---|---|
| `onnx/`, `step2/` ... `step6/` | Frontend steps |
| `step6b/net/`, `has/net_has/` | Exporters |
| `step6b/tb_fe_core_net*`, `has/tb_has_net*` | Build scripts |
| `has/insts_pe3/`, `has/insts_pe4/`, `has/vit_full/` | `fe_emit_insts.py`, `fe_vit_full.py` (shipped in the data package) |
| `reference_runs/` | Logs and per-tile counters of the reference runs (data package) |
| Run directories (log, metrics CSV, snapshot, roll-up) | Testbench runs and post-processing |

## 6. Editing guidelines

- `config_map.h` and `config_regs.h` must be changed together. The same applies to the `rtl_ref_` pair.
- The RTL-ref blocks mirror the RTL. Changes should be checked against the reference and re-validated on the
  tile-shape set (`BUILD_AND_RUN.md`) and the full network.
- A change to a shared header (`sauria_types.h`, `psm/obp_top.h`, `sram/sram_top.h`, `control/sauria_dma.h`,
  `driver/*`) affects both models. Rebuild and rerun the v4.5 regression (`tools/has/regress_native.sh`) as well
  as a network run. Build both the default configuration and the metrics configuration.
- Files generated by `tools/onnx_compiler.py` are overwritten on regeneration.
