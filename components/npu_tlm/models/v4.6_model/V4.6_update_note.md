# 📑 SAURIA NPU v4.6 Update Note: OBP Channel Sideband, Softmax/LayerNorm Overhaul & RE Integration

**Date**: September 15–October 4, 2026  
**Target Core**: SAURIA NPU Neo Core Lite 32 / 64   
**Scope**: Elimination of OBP Channel Timing Inference via PSM Hardware Sideband, OBP TFLite Symmetric Rounding & Shift UB Guards, Per-Vector Softmax Underflow & Stale-Slot Fixes, LayerNorm GroupNorm(1) Scope & Double Precision Accumulators, RE Requant Single-Rounding & Negative Tie Testing, Context ID Wiring Clarification, Scratch Overflow Tracking, and Top-Level Unified RE Integration Smoke Testing.

## 1. Executive Summary

Following a comprehensive code audit, numerical modeling, and architecture verification of the Output Boundary Pipeline (OBP) and Reduction Engine (RE) subsystem:
1. **OBP Requantization, Asymmetric Zero-Point & Memory Capacity**:
   - **Address Collision Fix**: Resolved critical address collision between OBP-A Zero-Point RAM (`0x00140000 + 0x60000 = 0x001A0000`) and OBP-B Scale RAM (`0x00160000 + 0x40000 = 0x001A0000`). Introduced configurable `ZP_OFFSET` template parameter in `Obp` mapped to free, non-SRAM regions: `0x001C0000` for OBP-A and `0x001D0000` for OBP-B. Updated `host_rdata_mux` in `npu_top.h` to decode both regions. Verified 100% collision-free writes and reads across all 8 per-channel RAMs in `tb_unified_smoke`.
   - **TFLite Symmetric Rounding**: Implemented symmetric round-half-away-from-zero:
     `if (shift > 0) product += (1LL << (shift - 1)) - (product < 0 ? 1 : 0);`
     Resolves the negative tie rounding discrepancy against TFLite (e.g. $x = -5, \text{shift} = 1 \implies -3$ in both OBP and TFLite).
   - **Shift UB Guard**: Added explicit guard `if (shift >= 64) val = 0.0;` on both integer and floating-point requantization paths, eliminating undefined behavior from unbounded register shifts.
   - **LUT Capacity & Modulo Indexing**: Pipelined activation LUT memory is sized to 64 lanes (`NUM_LUT_LANES = 64`) with safe index modulo masking (`% NUM_LUT_LANES`), resolving potential out-of-bounds memory accesses when `channel_idx >= Y_DIM`.
   - **PSM Channel Sideband**: Dedicated hardware bus `psm::o_channel_idx` $\to$ `obp::i_channel_idx` drives explicit channel indices, eliminating fragile valid-edge timing inference and ensuring 100% immunity to PSM pipeline drain bubbles ($1, 0, 0, 1, 1, \dots$).
2. **Reduction Engine (RE) Mathematical & Control Architecture**:
   - **Residual Skip Direct Binding & Test Hook Status**: Bound `re_inst_a/b->i_skip_data` directly to `s_residual_skip_a/b`, eliminating intermediate copies and sensitivity list omission bugs. Skip injection is classified as a simulation test hook (`set_residual_skip_a/b`), with no host MMIO or SRAM feeder path in this generation. Added `get_re_skip_data_in_a/b()` to directly observe sampled input data.
   - **Tile-Wide Softmax Scope & Dead-Code Fix**: Resolved dead-code issue where `switch (mode)` blocked bit-8 (`0x100`) mode matching; updated to `switch (base_mode)` (`base_mode = mode & 0xFF`). Documented limitation: computes a single joint distribution across the entire tile without row/channel grouping. Verified host MMIO writes for modes 7 and 8 (`F_RE_MODE_A/B`). Upgraded `tb_re` CASE 13 into CASE 13A (ascending order) and CASE 13B (descending order) with per-element double-precision reference check ($|got - exp| < 10^{-4}$) and tile sum == 1.0.
   - **RE to RCE LUT Delegation Status ("Hooked, Not Validated")**: Bidirectional hardware ports (`o_lut_*`) and companion RCE delegates (`m_rce_exp`, `m_rce_recip`, `m_rce_rsqrt`) are wired. When LUTs are empty, RCE falls back to standard math. Fully programming LUT tables requires redesigning input domains, as standard $[0, 1]$ reciprocity and rsqrt domains fail for Softmax sums $\ge 1.0$ and INT8 variances.
   - **Per-Vector Softmax Underflow Elimination**: Pass 1 now tracks per-vector maximums (`vector_max[scratch_wr_idx] = local_max;`). In Pass 2, each vector normalizes against its own maximum (`diff = orig_vec[l] - vec_max`), guaranteeing $\text{diff} \le 0$, $\max(\exp) = 1.0$, and non-zero exponent sums. Completely eliminates the bug where vectors with logits $> 104$ below the global max underflowed to all zeros in float32.
   - **Softmax Pass 2 Stale-Slot Read Guard**: In Pass 2, bounded `scratch_rd_idx` against $\min(\text{scratch\_wr\_idx}, \text{SCRATCH\_VECTORS})$. If Pass 2 streams more vectors than Pass 1 stored, it flags `scratch_overflow = true` and safely falls back to `in_vec` with `compute_max_tree(in_vec)` (rather than reading uninitialized slots with $- \infty$), preventing `+inf` exponents, NaNs, and undefined behavior during integer casting.
   - **RE Requantization Single-Rounding & Negative Tie Testing**: Replaced integer pre-truncation with single-step symmetric rounding `std::round(scaled / divisor)` guarded against `shift >= 64`. Tested in `tb_re` CASE 11B with negative tie ($in = -5, skip = 0, scale = 1, shift = 1 \implies -3$), and CASE 11C with exact golden vector matching (`{0, 0, 0, 0, 0, 2, 15, 110}`).
   - **LayerNorm Architectural Scope & Double Precision**:
     - *Scope Reclassification*: Marked as a **Known Architectural Limitation**. Current v4.6 hardware pools mean and variance across the entire tile, which mathematically implements sample-wide GroupNorm with $G=1$ (or tile-wide InstanceNorm). True per-token / per-pixel LayerNorm (as in ConvNeXt and ViT) requires $Y$-wide accumulators running across channel vectors.
     - *Double Precision Accumulators*: Upgraded `running_sum`, `running_sq_sum`, `running_mean`, and `running_var` from `float` to `double` in `ReductionEngine`, preventing precision loss and catastrophic cancellation ($E[x^2] - \text{mean}^2$) when the mean is large relative to spread in float32.
   - **Context Gate Wiring & Start Pulse Decoupling**: Verified `s_context_id_a` is local context ID ($0 \dots \text{ncontexts}-1$, per-tile local), resetting to 0 at the start of each tile and correctly arming the RE. Decoupled start pulse width via internal rising-edge detection (`start_edge`).
   - **Scratch SRAM Overflow Detection**: Added explicit overflow flag `scratch_overflow` and getter `has_scratch_overflow()` in `ReductionEngine`.

## 3. Deep Architectural Root Causes & Solutions

### A. Output Boundary Pipeline (OBP) Fixes

#### 1. Hardware Channel Sideband (`o_channel_idx`)
* **Problem**:  
  The PSM scan chain outputs $x_0$ in Phase 1 (`wren = 1`), pauses for 2 cycles during Phase 2 (scan enable) and Phase 3 (scan update wait) where `wren = 0`, then continuously streams $x_1 \dots x_{cxlim-1}$ in Phase 4. Inferring channel indices via valid-edge detection (`!prev_valid && i_valid`) caused $x_1$ to be interpreted as a new burst, resetting the channel counter and introducing an off-by-one index error.
* **Solution**:  
  The PSM drives a dedicated hardware sideband `o_channel_idx = shift_cnt` simultaneously with `o_sramc_wren` in Phase 1 and Phase 4 (`psm/psm_top.h:118, 140`). OBP samples `i_channel_idx` directly into Stage 1 registers on `i_valid`, completely eliminating `prev_valid` and internal counters (`psm/obp_top.h:302-304`).

#### 2. Symmetric Round-Half-Away-From-Zero & Shift UB Guard
* **Problem**:  
  Raw add-half-then-shift (`product += (1LL << (shift - 1))`) rounds negative ties toward $+\infty$ instead of away from zero. For example, $x = -5, \text{shift} = 1$: $(-5 + 1) \gg 1 = -4 \gg 1 = -2$, whereas TFLite round-half-away-from-zero produces $-3$. Furthermore, shift values from unbounded configuration registers $\ge 64$ trigger undefined behavior in C++ arithmetic shift.
* **Solution**:  
  Implemented symmetric negative tie adjustment and shift clamping in `psm/obp_top.h:339-357`:
  ```cpp
  if (shift >= 64)
  {
      val = 0.0;
  }
  else
  {
      int64_t product = static_cast<int64_t>(stage1_reg.biased_data[l]) * scale;
      if (shift > 0)
      {
          product += (1LL << (shift - 1)) - (product < 0 ? 1 : 0);
      }
      val = static_cast<double>(product >> shift);
  }
  ```
  Verified: $x = -5, \text{shift} = 1 \implies -3$; $x = +5, \text{shift} = 1 \implies +3$; $x = -3, \text{shift} = 1 \implies -2$; $x = +3, \text{shift} = 1 \implies +2$. Matches TFLite exactly.

### B. Reduction Engine (RE) Architecture & Numerical Stability

#### 1. Per-Vector Softmax Max (Underflow Elimination) & Stale-Slot Read Guard
* **Problem**:  
  Pass 1 maintained a single global `running_max` across all vectors in the tile, while Pass 2 computed exponent sums per-vector. If Vector 0 had logits near $+100$ and Vector 1 had logits near $-120$, Vector 1 computed $x - \text{running\_max} \le -210$. In IEEE-754 float32, $\exp(-210) = 0.0f$ underflows to zero, forcing the sum to 0, reciprocal to 0, and causing Vector 1 to output all zeros.  
  Additionally, Pass 2 previously checked `rd_idx < SCRATCH_VECTORS` without checking `rd_idx < scratch_wr_idx`. If Pass 2 streamed more vectors than stored, `vector_max` was read as $- \infty$, yielding $x - (-\infty) = +\infty$, $\exp(+\infty) = +\infty$, probability $\text{NaN}$, and undefined behavior during integer conversion.
* **Solution**:  
  In `psm/re_rce.h:518-535`:
  Pass 1 records each vector's own maximum in `vector_max[scratch_wr_idx] = local_max;`.  
  Pass 2 clamps valid reads to $\min(\text{scratch\_wr\_idx}, \text{SCRATCH\_VECTORS})$:
  ```cpp
  uint32_t max_valid_vectors = std::min(scratch_wr_idx, static_cast<uint32_t>(SCRATCH_VECTORS));
  bool valid_rd = (scratch_rd_idx < max_valid_vectors);
  if (scratch_rd_idx >= SCRATCH_VECTORS || (scratch_wr_idx > 0 && scratch_rd_idx >= scratch_wr_idx))
  {
      scratch_overflow = true;
  }
  psum_vector_t<Y_DIM, T_PSUM> orig_vec = valid_rd ? scratch_mem[scratch_rd_idx] : in_vec;
  float vec_max = valid_rd ? vector_max[scratch_rd_idx] : compute_max_tree(orig_vec);
  scratch_rd_idx++;
  ```
  The normalized diff is $x_l - \text{vec\_max} \le 0$, ensuring $\max(\exp) = 1.0f$ and the exponent sum is $\ge 1.0f$. Underflow is mathematically eliminated, and reads beyond written vectors safely fall back to `in_vec` and flag overflow without producing NaNs or undefined behavior.

#### 2. Requantization Single Rounding & Negative Tie Testing
* **Problem**:  
  RE requantization previously evaluated `int64_t qval = static_cast<int64_t>(norm * scale);` before adding the rounding half. Casting a float to `int64_t` truncates fractional bits toward zero, which caused double rounding and off-by-one errors.
* **Solution**:  
  Replaced with single-step symmetric rounding directly from float/double:
  ```cpp
  double scaled = static_cast<double>(norm) * static_cast<double>(scale);
  double divisor = (shift > 0) ? static_cast<double>(1ULL << shift) : 1.0;
  double rounded = std::round(scaled / divisor);
  out_vec[l] = static_cast<T_PSUM>(clamp_val<T_ACT>(rounded));
  ```
  Guarded against `shift >= 64` to prevent undefined behavior. Verified in `tb_re` CASE 11B with negative tie ($in = -5, skip = 0, scale = 1, shift = 1 \implies -3$) and CASE 11C with exact golden vector `{0, 0, 0, 0, 0, 2, 15, 110}`.

#### 3. LayerNorm: GroupNorm(1) Tile Limitation & Double Precision Accumulators
* **Architectural Scope**:  
  The current v4.6 Reduction Engine pools sum and sum-of-squares across all active lanes of all vectors in the tile, yielding a single scalar mean and variance. This implements **tile-wide GroupNorm with $G=1$** (InstanceNorm over the entire tile). It does *not* compute per-token or per-pixel LayerNorm across channels (which would require $Y$-wide accumulators running across vectors). This is documented as a known architectural limitation of the v4.6 reduction hardware.
* **Numerical Precision**:  
  To prevent catastrophic cancellation ($E[x^2] - \text{mean}^2$) when the mean is large relative to the spread in float32, `running_sum`, `running_sq_sum`, `running_mean`, and `running_var` are upgraded from `float` to `double` in `psm/re_rce.h`.

#### 4. Context Counter Wiring & Start Pulse Decoupling
* **Context ID Wiring**:  
  - In `control/main_controller.h:502`, `o_context_id.write(local_context);` outputs the per-tile local context ID ($0 \dots \text{contexts\_per\_tile}-1$).
  - In `npu_top.h:378`, `ctrl_inst_a->o_context_id` binds to `s_context_id_a`.
  - In `npu_top.h:1751`, `s_re_start_a.write(s_psm_start_a.read() && (s_context_id_a.read() == 0));` uses this local ID to arm the RE exclusively on the first context of each tile.
  - In `npu_top.h:381, 706`, `ctrl_inst_a->o_global_context_id` binds to `s_global_context_id_a`, which connects to `psm_inst_a->i_context_id` ($0 \dots \text{total\_contexts}-1$).
* **Start Pulse Decoupling**:  
  The controller FSM transitions `WAIT_OBUF` $\to$ `LAST_WAIT` unconditionally in 1 clock cycle (asserting `o_outbuf_start` for 1 cycle). Regardless of pulse width or wait states, the RE embeds an internal rising-edge detector (`bool start_edge = i_start.read() && !prev_start; prev_start = i_start.read();`), proven in CASE 12 to make the RE immune even if start is held high across multiple cycles.

#### 3. End-to-End Hardware Pipeline Execution Testbench (`tb_pipeline_re`)

The dedicated integration testbench `tb_pipeline_re.cpp` verifies complete hardware pipeline execution through all five stages:
$$\text{Systolic Array} \longrightarrow \text{PSM} \longrightarrow \text{OBP} \longrightarrow \text{Reduction Engine} \longrightarrow \text{SRAM-C}$$

It executes a two-pass hardware sequence on a 16x8 `NpuTop` instance:
* **Pass 1 (Bypass Mode, `F_RE_MODE_A = 0`)**:
  - Activations preloaded across 8 rows ($A[row] \in \{2, 5, 8, 12, 17, 23, 30, 38\}$), weights set to 1 across 16 columns for $K=8$.
  - Accelerator runs to completion in 175 cycles; unreduced output tensor $Y_{\text{obp}}$ is read back from SRAM C ($Y_{\text{obp}}[row][0] \in \{16, 40, 64, 96, 136, 184, 240, 304\}$).
* **Pass 2 (Live Reduction Mode, `F_RE_MODE_A = 5`, `RE_MODE_MAXPOOL`)**:

## 6. Status of the Five Architectural & Verification Items

Review and status update for the five architectural items:

1. **OBP Output Zero-Point ($Z_{out} \ne 0$)**:
   - **Status**: **Fixed (Math Correct, Address Collision Resolved)**.
   - **Root Cause & Resolution**: OBP-A's ZP RAM was previously mapped at `0x00140000 + 0x60000 = 0x001A0000`, which collided with OBP-B's scale RAM (`0x00160000 + 0x40000 = 0x001A0000`). Both OBPs decoded the same write, causing writes to OBP-B scale to unintentionally corrupt OBP-A per-channel zero-point and saturate OBP-A output. Furthermore, OBP-B ZP RAM (`0x001C0000`) was missing from `host_rdata_mux`.
   - **Fix**: Added configurable `ZP_OFFSET` template parameter to `Obp`. Mapped OBP-A to `0x001C0000` and OBP-B to `0x001D0000` (both free regions outside SRAM and RCE). Updated `host_rdata_mux` in `npu_top.h` to decode both `0x001C0000` (OBP-A) and `0x001D0000` (OBP-B).
   - **Verification**: Verified in `tb_unified_smoke` by writing distinct values to all 8 per-channel RAMs (OBP-A Bias, Scale, Shift, ZP; OBP-B Bias, Scale, Shift, ZP) with 100% readback accuracy and zero crosstalk, followed by an explicit collision check proving OBP-A ZP is untouched by writes to OBP-B Scale.
2. **Residual Skip Routing**:
   - **Status**: **Wired & Direct-Bound (Simulation Test Hook)**.
   - **Root Cause & Resolution**: `re_ctrl_mux_logic` copied `s_residual_skip_a/b` into `s_re_skip_data_a/b`, but those signals were omitted from the SC_METHOD sensitivity list, causing updates to be delayed until unrelated signals toggled.
   - **Fix**: Bound `re_inst_a/b->i_skip_data` directly to `s_residual_skip_a/b`, completely eliminating the intermediate signals and sensitivity list bugs. Note that OBP and RE share one skip signal (`s_residual_skip_a/b`). Port binding is present by code inspection and actively confirmed by querying `re_inst_a->i_skip_data.read()` directly through the RE module instance's own input port via `get_re_skip_data_in_a/b()`.
   - **Architectural Scope**: The skip vector currently arrives only via top-level C++ simulation setter methods (`dut->set_residual_skip_a/b()`), with no host MMIO or SRAM feeder path in this generation. It is accurately designated as a simulation test hook rather than autonomous hardware routing.
3. **RE Driving Companion RCE Non-Linear LUTs**:
   - **Status**: **Hooked, Not Validated**.
   - **Root Cause & Scope**: RE delegates (`m_rce_exp`, `m_rce_recip`, `m_rce_rsqrt`) and hardware port driving (`o_lut_op`, `o_lut_in`, `o_lut_valid`) are wired. However, `o_lut_*` writes happen inside an unclocked loop over lanes within a single cycle, so only the last lane is visible on the signals. With empty LUT tables, the RCE falls back to standard math library implementations (`std::exp`, `1.0/x`, `1.0/std::sqrt`).
   - **Limitation**: Programmed LUTs would break under current LUT domain mappings: `lookup_recip` maps $x \times 511$ over $[0, 1]$, but a Softmax exponent sum is always $\ge 1.0$, which would saturate to `lut[511]/511` ($\approx 0.5$, incapable of representing $\text{recip}(1.0) = 1.0$). Similarly, `lookup_rsqrt` is mapped over $[0, 1]$, which does not suit INT8 variance scales. Validating programmed LUTs requires a domain rescaling architecture.
4. **Tile-Wide Softmax ($D > Y\_DIM$)**:
   - **Status**: **Fixed (Scope Documented)**.
   - **Technical Details**: The online math is verified correct: it rescales the running exponent sum by $\exp(\text{old\_max} - \text{new\_max})$ whenever a new maximum is encountered.
   - **Dead-Code Elimination**: In `re_rce.h`, updated `switch (mode)` to `uint32_t base_mode = mode & 0xFF; switch (base_mode);`. Previously, passing `mode | 0x100` hit `default:` as a silent no-op, making internal `(mode & 0x100)` checks dead code.
   - **Host Register Validation**: Verified host MMIO writes of mode 7 (`RE_MODE_SOFTMAX_TILE_PASS1`) to `CFG_OUT_OFFSET + 0x2C` and mode 8 (`RE_MODE_SOFTMAX_TILE_PASS2`) to `CFG_OUT_OFFSET + 0x3C`.
   - **Numerical Testing**: Upgraded `tb_re` CASE 13 into CASE 13A (ascending order inputs 0..37, triggering online rescale on every vector) and CASE 13B (descending order inputs 37..0, where global maximum appears in vector 0). Verified exact per-element double-precision golden probability vectors ($|got - exp| < 10^{-4}$) and confirmed tile sum == 1.0 for both.
   - **Scope Limitation**: Normalization operates across the entire tile as a single joint distribution. There is no row/channel grouping parameter; multi-row tiles share a single global normalization.
5. **Full-Pipeline Execution Coverage**:
   - **Status**: **Verified & Closed (Hardware Full-Pipeline Proof via `tb_pipeline_re`)**.
   - **Scope & Resolution**: To definitively provide verified hardware proof that live tensor data flows end-to-end through the Reduction Engine inside `NpuTop`, `tb_pipeline_re.cpp` was developed and executed. The test performs an end-to-end hardware pipeline execution:
     1. Preloads SRAM A and SRAM B via MMIO with varying activations and weights.
     2. **Pass 1 (Bypass Mode, `F_RE_MODE_A = 0`)**: Executes full physical compute `SystolicArray -> PSM -> OBP -> SRAM-C`, reading back unreduced tensor $Y_{\text{obp}}$ with varying row values.
     3. **Pass 2 (Live RE MaxPool, `F_RE_MODE_A = 5`)**: Executes identical activations through the live hardware pipeline with `re_ctrl_mux_logic` routing OBP stream to `re_inst_a`, which calculates row maximums and streams through `sramc_wdata_mux_logic` into SRAM C.
     4. **Mathematical & Physical Assertions**: Confirmed all 16 active columns match vector maximum ($Y_{\text{re}}[l] == \max_k(Y_{\text{obp}}[k])$), and confirmed that the hardware RE actively altered the live stream in-flight ($Y_{\text{re}} \ne Y_{\text{obp}}$).
     - **Verification**: `./tb_pipeline_re` passes 12 of 12 assertions (**12 / 12 PASS**). Full-model ONNX tests (`test_yolo`, `test_onnx_model`) remain running in bypass mode by design.
