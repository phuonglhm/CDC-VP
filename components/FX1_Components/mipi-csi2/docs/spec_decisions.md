# CSI-2 RX VP — specification decisions (M0)

Status: **draft for review, 2026-10-19.** Every decision below marked
**VP decision – pending IP confirmation** is a value chosen so that the virtual
platform, the driver and the tests can be written against one contract. It is
not a statement of what the RTL does. When the IP team answers, the decision is
updated here first, then in code and tests.

Companion documents:

- [REGISTER_CONTRACT.md](REGISTER_CONTRACT.md): the 55 registers of workbook v1.4
  and their side effects.
- [PHY_ADAPTER_CONTRACT.md](PHY_ADAPTER_CONTRACT.md): mapping of the controller
  PPI to the `mipirxphy` model, model-derived startup sequence.

   (reads 0, writes ignored). No VP code writes meaning into reserved bits.
2. Where the workbook is silent and MAS is explicit and non-contradicting, MAS
   applies (e.g. read-pop of GENERIC_SHORT_PACKET, W1C precedence).
3. Where neither defines a value, this file defines it as a VP decision.

### 2.1 Documentation conflicts D01–D12

| ID | Decision (value used by VP) | Rationale | Owner | Tests |
|---|---|---|---|---|
| D01 | `IP_VERSION` reads **0x0001_0100**. Driver `probe` accepts major 1, minor 1; any other value fails probe with a distinct error code. | Workbook is rank 2; MAS value 0x0001_0200 is a different revision. | IP | `csi2_csr_reset`, `csi2_drv_probe` |
| D02 | `STREAM_CONFIG` reset **0x3** (axis_enable=1, packed). `stream_follow_dma_drop` not implemented. | D03 | `DMA_ATTR` is **RW, reset 0** (workbook). `max_burst_len` encodes **beats − 1** (0 → 1 beat, 255 → 256 beats), clamped to MAX_BURST_BEATS=256. `max_outstanding` is RW storage; effective limit = `clamp(max_outstanding, 1, 8)`, 0 behaves as 1. In the VP the TLM worker is serial, so the observable limit is 1 regardless (see §2.4). | Beats−1 matches AXI AWLEN and MAS "max_burst_len + 1" (META_MAX_BURST_BEATS row). | D04 | **RAW-only DMA** in the first milestone. Offset 0xB8 stays reserved. `DMA_BUFFER_SIZE` = byte size of one ping-pong side, entirely RAW. No metadata area is written by hardware. | D05 | `ERROR_CAPTURE` holds the **most recent** protocol error (last writer wins). Trigger set taken from MAS: IRQ bits 1, 3, 4, 6, 8, 19. Cleared by soft_reset. Frame id and line number: C33. | Workbook field text says "most recent"; MAS first-of-newest-capture contradicts it. | IP | `csi2_err_capture_multi_error` |
| D06 | Every capture that opens ends **exactly once**, as *dropped* or *delivered*. **Dropped** = ended without any buffer released to software: Control FSM drop, DMA could not claim (no HW_OWNED side, `dma_start`=0, `dma_abort`=1, misaligned, M04/M10/M11), DMA abort with `err_frame_policy`=0 → FRAME_DROP_COUNT+1, `frame_dropped`. **Delivered** = every other end: with `dma_enable`=1 the side is released as SW_OWNED_VALID or SW_OWNED_ERROR (also after an abort with policy 1, M16); with `dma_enable`=0 the FE reached the stream path → FRAME_COUNT+1, `frame_received`, raised at the capture's end. Invariant: ended captures = FRAME_COUNT + FRAME_DROP_COUNT. Neither `frame_received` nor FRAME_COUNT proves the data is valid; only `buf_done_ok` / SW_OWNED_VALID does. | IP | `csi2_counters_drop_invariant`, `csi2_abort_policy1_counts_delivered` |
| D07 | 0x000–0x0FF: OKAY; reserved offsets in this range read 0, writes ignored. 0x100–0xFFF: **DECERR** (`TLM_ADDRESS_ERROR_RESPONSE`), no side effect. 0x1000 and above is outside the 4 KiB aperture, decoded by the bus, never aliased. | MAS §8 explicit; workbook silent. | IP, SoC | `csi2_csr_reserved_and_hole` |
| D08 | DMA layout: see §2.3. | Workbook gives no encoding/stride formula. | IP, FW | §2.3 |
| D09 | **Linear profile is a build-time parameter** of the controller: `exposure_count=1`, active VC set = {VC0}. A capture completes at FE of VC0. Dual-VC (HDR) profile is a separate build, milestone M8. | User decision 2026-10-19; MAS hardwires dual_vc on RX path (F04); no CSR field exists. | IP | `csi2_linear_single_frame_no_vc1`, `csi2_linear_fe_then_stop` |
| D10 | Requirement V4 envelope: 4 lanes, RAW10/RAW12. VP lane tests: 1/2/4 lanes. First HS rate: one point in **500–1000 Mb/s/lane without deskew**, exact value fixed by the PHY adapter contract. ### 2.2 CSR access semantics

| ID | Decision | Owner | Tests |
|---|---|---|---|
| C01 | RO and reserved bits: writes ignored. WO bits read 0. RW1C: writing 1 clears, 0 keeps. | IP | `csi2_csr_access_types` |
| C02 | W1C race: an event at the same simulation time as the clearing write **keeps the flag set** (MAS §8). The VP applies the clear, then any event of the same timestamp. | IP | `csi2_irq_w1c_race` |
| C03 | `IRQ_STATUS` write response is returned immediately in the VP. The MAS response stretching (IRQ_CLR_TIMEOUT) is not modelled; a flag re-set by an event is simply visible on the next read. | VP | — |
| C04 | Access size: TLM length **exactly 1, 2 or 4** bytes inside one 32-bit word; byte enables honoured (a byte lane not enabled is unchanged). Any other length (0, 3, > 4) or an access crossing a word → `TLM_GENERIC_ERROR_RESPONSE` (SLVERR) **before any side effect** (no FIFO pop, no timestamp snapshot, no write). Debug transport applies the same size rule. | VP | `fx1_csi2_ctrl_csr_partial` |
| C05 | Side-effect reads (GENERIC_SHORT_PACKET pop, TIMESTAMP_LO snapshot) happen only on `b_transport` reads. `transport_dbg` reads are side-effect free; `transport_dbg` writes are not supported (return 0 bytes). | VP | `csi2_csr_dbg_no_side_effect` |
| C06 | `TIMESTAMP_LO` read snapshots the upper 32 bits into the shadow returned by `TIMESTAMP_HI`. Reading HI without a prior LO returns the last shadow (0 after reset). | IP | `csi2_timestamp_snapshot` |
| C07 | Timestamp counter = simulation time in ns since `resetn` release (equivalent to TS_INCR at any sys_clk). Cleared by `resetn`/`full_reset` only, not by `soft_reset`. | VP | `csi2_timestamp_monotonic_soft_reset` |
| C08 | `IRQ_STATUS` flags set whatever the masks hold. `irq = global_enable && |(IRQ_STATUS & IRQ_ENABLE)`. **Event suppression** applies to the *reset* causes only — `soft_reset`=1, `full_reset`, `resetn` and the PHY reset pulse: events raised then are not recorded. **VP deviation:** RST_TAIL (256 sys_clk after release, MAS) is not modelled as a cycle count, because the TLM model has no CDC synchronisers that could hold an in-flight event; instead every event carries the reset epoch of its source and a stale-epoch event is never recorded (M13). Disable/abort drains (M17) do **not** suppress events: their finalisation events must be seen. | IP | `csi2_irq_mask_global`, `csi2_irq_no_event_after_reset` |
| C09 | Counters saturate at their field maximum (16-bit fields at 0xFFFF; 32-bit counters at 0xFFFF_FFFF). Cleared by `soft_reset`, `resetn`, `full_reset`. | IP | `csi2_counter_saturation` |
| C10 | `soft_reset` clears every hardware-owned status field of the datapath: CORE_STATUS stickies/levels, BUFFER_STATUS, LANE_ALIGN_STATUS, LANE_STATUS SoT stickies, all counters, IRQ_STATUS, the generic short-packet FIFO, VCn_IMAGE_INFO*, EMBEDDED_DATA_INFO_*, ERROR_CAPTURE, AXI_FAULT_*, EMB_EXTRACT_VCn_VALm, TIMESTAMP_LO/HI and their shadow, PROTOCOL_CONFIG.active_lanes_applied. Kept: every RW configuration register, the timestamp counter (C07), BUFFER_OWNERSHIP, FRAME_ID, BUFFER_ERROR_INFO, DMA_STATUS.active_buffer (M15), and PHY-mirrored live fields (P11). | IP | `fx1_csi2_ctrl_soft_reset_scope`, `fx1_csi2_ctrl_counters`, `fx1_csi2_ctrl_gsp`, `fx1_csi2_ctrl_timestamp` |
| C11 | LANE_STATUS.laneN_sot_error / sot_sync_error are **sticky**: set by an `errsoths`/`errsotsynchs` pulse of an enabled lane (sampled on `rxbyteclkhs`), cleared by `soft_reset`, `full_reset`, `resetn`. The workbook is silent; a one-byte-clock pulse is otherwise unobservable by software. | IP | `fx1_csi2_ctrl_phy_events` |
| C12 | CORE_STATUS.dt_conflict is a live level computed from METADATA_DT_CONFIG ("set while", workbook row 47), not a sticky; `soft_reset` cannot clear it while the configuration persists. | IP | `fx1_csi2_ctrl_csr_access` |
| C13 | PROTOCOL_CONFIG.active_lanes stores any written value. Lane Management adopts it only in ST_IDLE. The reserved `10` is not adopted (`active_lanes_applied` keeps its value). A value above MAX_LANES **is** adopted, as MAS Block 2 states: the lane slices that are not built never arm, so every burst aborts. | IP | `fx1_csi2_rx_lm_lanes` |
| C14 | IRQ sources owned by the PHY side: `sot_error` (9) / `sot_sync_error` (10) on `errsoths` / `errsotsynchs` of an enabled lane; `stop_state` (11) on a 0→1 transition of `stopstatedata` of an enabled **data** lane (the clock lane is not a source). Every PHY bring-up therefore raises bit 11; MAS step 11 clears it. | IP | `fx1_csi2_ctrl_phy_bringup`, `fx1_csi2_ctrl_phy_events` |
| C15 | While `resetn`=0 the register file is held in reset: CSR reads return 0, writes are ignored, both with OKAY (the AXI4-Lite interface has its own `lite_aresetn`, not modelled). CSR access latency is a constructor parameter, default 0. | VP | — |
| C16 | **One packet per HS burst** (MAS Packet FSM): after a packet is retired, words without `sob` are ignored until the next burst. This absorbs the 6–8 trail/EoT bytes this PHY delivers after the payload (PHY_ADAPTER_CONTRACT §4.2) and requires the sensor to send one packet per burst. Short packets 0x02/0x03 (LS/LE) and the reserved 0x04–0x07 are ignored without error. A burst shorter than the 4-byte header: C21. | IP | `fx1_csi2_rx_pa_frames`, `fx1_csi2_rx_pa_routing` |
| C17 | Timing model of the receive path: Lane Management is cycle-accurate on `rxbyteclkhs` (PPI sampled on every rising edge). **M3a**: Packet Analyzer processed each merged word at the edge that produced it (ideal FIFO, protocol baseline only). **Since M3b** Packet Analyzer and Blocks 4–12 run as a `sys_clk` cycle model (C24) behind a bounded asynchronous FIFO (C25); occupancy, service rate and overflow are modelled and tested. | VP | `fx1_csi2_sys_pipe_cdc`, `fx1_csi2_rxphy_frame_*` |
| C18 | **Deviation from MAS Block 2** (Lane Event Capture): flags are clear-dominant in ST_IDLE/ST_ABORT **except in the cycle that opens a burst from ST_IDLE**. This PHY asserts `rxactivehs` and `rxsynchs` on the same `rxbyteclkhs` edge and presents the first byte one cycle later; MAS (PG202 timing) has `rxactivehs` first and the first byte with `rxsynchs`. Without the exception every burst of this PHY aborts as unarmed (shown by mutation on the real PHY). Both PPI conventions are covered by unit tests. | IP | `fx1_csi2_rx_lm_merge`, `fx1_csi2_rxphy_frame_*` |
| C19 | With this PHY a lane that never synchronises is reported as **`abort_fifo_full`**, not `abort_unarmed` / `abort_sync_err`: the synchronised lanes deliver data plus trail bytes before the burst closes or the PHY reports `errsotsynchs`, filling the 6-byte usable delay FIFO. `abort_lane_sync_seen` identifies the failing lane in every case; drivers diagnose with it. | IP, FW | `fx1_csi2_rxphy_errors`, `fx1_csi2_rxphy_unarmed` |
| C20 | `soft_reset` reaches Lane Management in the `rxbyteclkhs` domain (MAS Block 2). A 0→1 transition is **latched as a request** that the next byte-clock edge applies, so a pulse shorter than a byte-clock period (two back-to-back CSR writes) is not lost. `reset_in_progress` stays 1 until that edge while the clock lane is in HS (`cl_rxclkactivehs`); with the byte clock stopped it does not wait (MAS: soft_reset has no effect then; use `full_reset`), and the request is applied at the first edge after the clock restarts. The driver returns `FX1_CSI2_ENOCLK` in that case instead of OK. `full_reset`/`resetn` reset Lane Management directly and clear the request. | IP, FW | `fx1_csi2_rxphy_soft_reset_aligned`, `_latency`, `_noclk`, `fx1_csi2_rx_lm_reset_states` |
| C21 | A burst whose first word has fewer than 4 bytes is **not decoded** (bytes not received are no evidence for the ECC): no FS/FE/GSP/payload, not counted in PACKET_COUNT or the ECC counters. It is reported as a truncated packet — IRQ `wc_corruption`, ERROR_CAPTURE with `fault_vc`=3 — and marks every open frame in error (frame-level error at its FE), like a discarded burst. | IP | `fx1_csi2_rx_pa_short_header` |
| C22 | End of burst before a long packet is complete — payload **or** CRC footer missing, including WC = 0 with a header-only burst — is a truncated packet: IRQ `wc_corruption`, ERROR_CAPTURE, frame marked in error. It is not reported as a CRC error (no CRC verdict exists). PACKET_COUNT still counts it (header passed ECC, MAS). The payload already delivered (cut-through) is invalidated through the frame-level error. | IP | `fx1_csi2_rx_pa_missing_footer` |
| C23 | Event order per long packet at the Packet Analyzer outputs: payload beats, the last with EOL, **then** the integrity result (CRC error or truncation), **then** packet_done; FS/FE results follow their packet. Matches MAS ("err_crc not earlier than the cycle after bp_eol"); consumers may discard the line on the error without a later beat of it arriving. | IP | `fx1_csi2_rx_pa_order` |

### 2.3 DMA RAW layout (resolves D08)

| ID | Decision | Owner | Tests |
|---|---|---|---|
| M01 | `dma_format`: 0 = bypass (packed RAW10/RAW12), **1 = RAW16** right-aligned (HAS v1.2 Table 4-27 row 24). Reset 0. FW sets 1 for the Requirement V4 RAW16 baseline. | IP, FW | `csi2_dma_format_{packed,raw16}` |
| M02 | Line stride = `bytes_per_line + line_padding`. Line *n* starts at `base + n × stride`. Padding bytes are never written. | IP | `csi2_dma_stride_padding` |
| M03 | `bytes_per_line` must equal the produced line size: RAW16 `2W`, RAW10 packed `5W/4`, RAW12 packed `3W/2`. A longer line is a **layout error**: the extra bytes are not written and the capture ends as a DMA fault (`buffer_overflow` + policy of M07). A shorter line leaves the rest of the line untouched and is reported by the resolution check, not by the DMA. | IP | `csi2_dma_line_too_long`, `csi2_dma_line_short` |
| M04 | Alignment: `DMA_BUFFERn_ADDR`, `bytes_per_line + line_padding` multiple of **8** (AXI beat, AWSIZE=3). A misaligned configuration makes the DMA refuse the claim: the capture is dropped (`frame_dropped`, FRAME_DROP_COUNT) and nothing is written. FW additionally uses 16-byte alignment when the buffer is handed to the ISP. | IP, FW | `csi2_dma_misaligned_refused` |
| M05 | Bounds: before each burst the DMA checks `line_offset + burst_end ≤ DMA_BUFFER_SIZE` using 64-bit arithmetic; on violation nothing of that burst is written and the capture ends as a DMA fault. `DMA_BUFFER_SIZE=0` therefore faults on the first line. | IP | `csi2_dma_size_overflow`, `csi2_dma_addr_wrap` |
| M06 | Bursts: INCR, 8-byte beats, length ≤ `max_burst_len+1`, split at every 4 KiB boundary and at every line end. WSTRB from the line tail. | IP | `csi2_dma_4k_split` |
| M07 | `err_frame_policy` decides how an **aborted** capture (M16) is finalised: 0 = discard and rewind (side stays HW_OWNED, write pointer back to base, `frame_dropped`, FRAME_DROP_COUNT+1); 1 = release with error (side → SW_OWNED_ERROR, BUFFER_ERROR_INFO, `buf_done_err`). Latched at claim with the rest of the configuration (M09). | IP | `csi2_dma_fault_policy_{0,1}` |
| M08 | `last_valid_line` = index of the last line whose every write got an OKAY response, 0-based; **0xFFFF when no line completed**. | IP | `csi2_dma_last_valid_line` |
| M09 | Claim at Frame Start: base, size, pitch, attributes and `err_frame_policy` are latched for the whole capture; CSR writes during a capture take effect at the next claim. **`dma_format` is not latched** (review M4a F2, user decision 2026-10-20, MAS Block 8: Format Bridge applies it live, not shadowed): software changes it only while `dma_enable` = 0 and `DMA_STATUS.dma_busy` = 0; a change otherwise is unsupported, the VP warns and the layout of the captures concerned is undefined. Same rule for `STREAM_CONFIG.stream_format` with `axis_enable` = 0. The M4b driver enforces it. | IP, FW | `fx1_csi2_dma_cfg_latched`, `fx1_csi2_rxphy_dma_sensor` |
| M10 | The DMA claims a side only while `dma_enable && dma_start && !dma_abort` (level RW bits) and `core_enable`. While `dma_enable`=0 the DMA path does not take part (no claim, no event). While `dma_enable`=1 but `dma_start`=0 or `dma_abort`=1, a capture that starts is not claimed and counts as a DMA drop (`frame_dropped`, FRAME_DROP_COUNT). | IP | `csi2_dma_abort_held_drops` |
| M11 | Side selection at claim: try the side after the last completed one; if it is not HW_OWNED try the other; if neither → drop (`frame_dropped`). Reset: both sides HW_OWNED (`00`). Release (`BUFFER_RELEASE`) of a HW_OWNED side has no effect. | IP | `csi2_own_both_locked_drop`, `csi2_own_release_hw_noop` |
| M12 | Completion: `buf_done_ok` and `SW_OWNED_VALID` only after FE **and** every write response of the capture is OKAY. Ownership, FRAME_ID and BUFFER_ERROR_INFO are updated before the IRQ flag is set (same timestamp, visible together). | IP | `csi2_dma_done_after_responses` |
| M13 | **Reset** (`soft_reset` 0→1, `full_reset`, `resetn`) during a capture: no new write is issued; writes already issued cannot be recalled and may still reach memory, so the DMA waits for their responses (drain). The reset start latches **`reset_drain_pending`**, which clears only when every write issued before that reset has its response and the side being written is finalised **without any event** — rewound to HW_OWNED (`soft_reset`) or `00` with the other side (`full_reset`/`resetn`). It is independent of the level of `soft_reset` and of the `resetn` pin: a short `soft_reset` pulse, or `resetn` asserted and released before the old responses return, keeps it set until the drain ends (the register file itself is reset as usual). A new reset during the drain increments the epoch again and extends the drain to all writes issued so far. Every claim carries a reset epoch; a reset increments it, and anything that completes with an older epoch publishes nothing. | VP | `csi2_dma_reset_mid_frame`, `csi2_dma_reset_outstanding_write`, `csi2_soft_reset_pulse_delayed_response` |
| M15 | Neither an abort (M16) nor `soft_reset` changes a side that is already SW_OWNED_*: software may still be reading it (RAW12 zero-copy to ISP). Only the side being written is finalised. Only `full_reset`/`resetn` force both sides to `00`. | IP | `csi2_soft_reset_keeps_sw_owned`, `csi2_abort_keeps_sw_owned` |
| M16 | **Abort** of a capture in flight, for any of these causes: AXI SLVERR/DECERR, layout or bounds fault (M03–M05), `dma_abort` 0→1, `core_enable` 1→0, `dma_enable` 1→0. Sequence: (1) stop issuing writes of this capture, unissued data discarded; (2) drain: wait for every issued write response; (3) finalise **exactly once** per M07, publishing ownership, BUFFER_ERROR_INFO and the IRQ flag together (M12). The epoch does not change, so the finalisation is always published. An aborted capture never produces `buf_done_ok`. A second abort cause during the drain changes nothing. With no capture in flight an abort cause only blocks new claims. | IP | `csi2_dma_abort_policy0_mid_frame`, `csi2_dma_abort_policy1_mid_frame`, `csi2_dma_abort_delayed_response` |
| M17 | `DMA_STATUS.dma_busy` = 1 from claim until finalisation (including drain), and while `reset_drain_pending`. `CORE_STATUS.reset_in_progress` = `soft_reset` OR PHY reset pulse active OR **`reset_drain_pending`** (M13; covers `soft_reset` pulses and the `full_reset` drain) OR **`disable_drain_pending`**, where the latter starts at `core_enable` 1→0, `dma_enable` 1→0 or `dma_abort` 0→1 with a capture in flight and ends when M16 step 3 is published. While `reset_in_progress` = 1 the DMA claims no side, whatever the current level of `soft_reset`. `reset_in_progress` falls in the same timestamp as the last pending finalisation, so a 0 read means no old write can still land and ownership is final. PHY readiness after the pulse is **not** covered: use stop-state (P04). | IP | `csi2_reset_in_progress_disable_drain`, `csi2_soft_reset_pulse_delayed_response`, `csi2_no_stale_event_after_reenable` |
| M14 | AXI ID: RAW buffer 0 → AWID 0, buffer 1 → AWID 1 (MAS AXI_ID_WIDTH row). QoS/PROT carried in a TLM extension when the FX1 bus supports it, otherwise documented as not observable. | SoC | `csi2_dma_fault_trace` |
| M18 | **Binding of beats to captures.** The claim is made at the capture's lead Frame Start (Frame Context `capture_start`), FRAME_ID and DMA_STATUS.active_buffer are written then. Every pixel entry carries, as a VP sideband not present on the MAS buses, the frame id of its capture (set at the Line Buffer write port, carried through Format Bridge like `vc_tag`); the DMA writes a beat into the buffer of that capture, or discards it when the capture has no buffer. This is the binding MAS gives the DMA through `ctx_slot` at `ev_fs`, kept exact when the Frame Start of the next frame is decoded while the tail of the previous one is still in Line Buffer. A capture's input is complete at its Frame End once a beat of another capture reaches the DMA or the pipeline (Byte-to-Pixel, Line Buffer, Format Bridge DMA side) is empty, so a single frame followed by a stopped sensor completes. | VP | `fx1_csi2_dma_back_to_back`, `fx1_csi2_dma_frame_*` |
| M19 | **Capture ledger**: every capture that opens ends exactly once (D06). Dropped by Control FSM (`capture_dropped`: CRC, ECC, lane abort, Line Buffer full, core disable) → **dropped**, even when its buffer is released with error under policy 1 (user decision 2026-10-20: `buf_done_err` and SW_OWNED_ERROR, but no `frame_received` / FRAME_COUNT). DMA path not taking part (`dma_enable` = 0 at the capture start) → delivered at its end. Otherwise the DMA outcome: released valid, or released with error after an abort caused by the DMA (AXI error, layout, bounds, FIFO overflow, `dma_abort`, `dma_enable` / `core_enable` 1→0 on a capture Control FSM did not drop) → delivered; rewound (policy 0) or claim refused → dropped. Resolved when both the Frame End and the DMA finalisation are known, in Frame Start order; `frame_received` / FRAME_COUNT or `frame_dropped` / FRAME_DROP_COUNT in the same timestamp as the finalisation (M12). | C33 | **ERROR_CAPTURE** keeps the D05 policy (most recent). `fault_frame_id` = frame id of the capture the channel belongs to (0 while orphan), the newest capture for an unknown channel; `fault_line_number` = image lines of the channel completed (CRC error: 1-based index of the failing line; truncated packet: lines before it), **0xFFFF** for an unknown channel (MAS Block 11). | IP | `fx1_csi2_rxphy_errors` |
| C34 | **FRAME_COUNT / frame_received in M3b** (D06 with the DMA not built): a capture that ends without a Control FSM drop is delivered (FRAME_COUNT+1, `frame_received`); a dropped one is counted in FRAME_DROP_COUNT with `frame_dropped`. | C36 | Checks follow MAS literally, with consequences for software: with EXPECTED_RESOLUTION = 0 (reset) every frame with image lines raises `resolution_mismatch` (no enable bit), so FW programs it before stream-on; the frame-number check compares with the previous FS of the channel, 0 after reset, so a first frame numbered above 1 raises `frame_num_seq_err` when `fnum_check_en` = 1. | FW | `fx1_csi2_sys_fc_checks` |
| C37 | **core_enable 1→0 is latched** for the `sys_clk` domain (review M3b F1, re-review R1). The write resets Packet Analyzer and flushes the receive FIFO at once, and latches a stop. Until the stop has **completed**, Frame Context, Control FSM and the TPG see `core_enable` = 0 and the receive FIFO is held flushed (bursts arriving meanwhile are discarded), whatever the CSR level. **Completion** = every open capture has ended as dropped, Control FSM is in ST_IDLE (after HOLD/FLUSH when a capture or a line was open) **and** the stream master's Finalize Sequencer is back in PASSTHROUGH, i.e. the abort the stop requested has finished: the held beats were accepted and the last abort beat was accepted. Issuing the abort request is not completion. A stop that needs no abort (idle) completes within a few cycles; with the ISP holding TREADY low the stop stays pending (no deadlock without a sink: an absent sink is always ready). The DMA response drain of M16/M17 is a separate obligation (M4). | IP | `fx1_csi2_sys_ctl_core_pulse`, `fx1_csi2_rxphy_core_pulse_lat0/_lat1/_lat20` |
| C38 | **Image packet with WC = 0** (RAW10/RAW12, header and CRC correct; review M3b F2, re-review R2): accepted without error and **not a line** anywhere: it produces no beat, does not advance the line count of the Frame Supervisor (Packet Analyzer, the line number given with its errors) nor of the Geometry Accumulator (so `height_mismatch` reports it when EXPECTED_RESOLUTION is set), and does not consume the first-image mark: SOF rides on the first payload beat actually delivered in the frame, exactly once.
