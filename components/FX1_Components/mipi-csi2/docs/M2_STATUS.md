## Test run

`ctest -L fx1_csi2` after the review fixes (2026-10-20): **48/48 passed**
with `-j4` (29 `fx1_csi2_unit`, 19 `fx1_phy_slow`). Each test process elaborates the
PHY (~5 s); PHY bring-up cases add ~3 s per startup.

```bash
export CC=/usr/bin/gcc
export CXX=/usr/bin/g++
export PATH=/usr/bin:/bin:$PATH
# sanity
$CC -dumpfullversion
$CXX --version | head

cmake -S components/FX1_Components/mipi-csi2 -B /tmp/csi2-build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DSYSTEMC_HOME=/opt/systemc-2.3.4
cmake --build /tmp/csi2-build -j8 --target fx1_mipi_csi2_all
```

## Known limits and open items

1. No datapath yet: packet/frame counters, frame context, line buffer, TPG, DMA and ownership transitions have storage, semantics and hooks but no producer until M3/M4.
2. Drain behaviour (M13/M16/M17) is verified with a simulated DMA through the hooks; the delayed-response DMA test (`csi2_soft_reset_pulse_delayed_response` with real outstanding writes) is M4.
3. P08–P11 are VP decisions: PHY rate configuration is not software-programmable, `phy_enable` uses the PHY's shutdown, PHY-mirrored fields can differ from workbook reset values.
4. The controller is not instantiated in `fx1_soc` (M5); address 0x1104_0000 / IRQ 7 remain placeholders (P01). The driver has not been cross-compiled for RISC-V yet.
5. ULPS, deskew and rates other than 800 Mb/s remain unverified (M1 limits).

## Review 2026-10-20 (plan/M2_REVIEW_20261020.md) — resolution

| ID | Finding | Resolution |
|---|---|---|
| F1 (P1) | `resetn` cleared the capture/drain state: `reset_in_progress` and `dma_busy` read 0 after release with old writes outstanding | `resetn_method` keeps `capture_in_flight_`, turns any capture in flight or unfinished drain into `reset_drain_pending` (drain request event), supersedes an abort drain; a reset during a drain increments the epoch again (`start_reset` likewise). M13 text names `resetn` explicitly. Test `fx1_csi2_ctrl_reset_drain_resetn`. |
| F2 (P2) | a 3-byte CSR access returned OKAY and popped the GSP FIFO | size must be 1, 2 or 4 (b_transport and transport_dbg) before any side effect; C04 reworded; `csr_partial` covers size 3 at lanes 0 and 1 for a RW register, the GSP FIFO (bus and debug) and the TIMESTAMP_LO snapshot (made observable with `hw_latch_timestamp_ns`). |
| F3 (P2) | 32-bit accumulated wait could wrap: endless polling | remaining-budget loop, each step `min(poll, remaining)`, `poll_us` 0 taken as 1; total requested delay = timeout exactly. Five fake-HAL tests. |

The reviewer's repro script, run on a copy against the fixed build: `resetn=0 size3=0 timeout=0`.

Observation for M5 (F10 of the plan review): advancing simulated time is not free even with the PHY in shutdown — an attempt to idle 4.4 s simulated in a controller test did not finish within 120 s wall. The cost of long idle phases (DDR preinit) with the PHY instantiated must be measured before M5 integration.
