# POSI Block

## Overview

POSI stands for **Post-Intra Prediction**.

This block is the second stage of the intra prediction path in the VPU TLM model. POSI receives intra mode candidates from PREI and generates the actual intra prediction pixels.

This is a **functional TLM model**, not a cycle-accurate RTL model.

## Role in VPU Pipeline

POSI belongs to the intra prediction path:

```text
Input Frame
    ↓
PREI
    ↓
POSI
    ↓
Intra prediction_result
```

POSI generates the final intra prediction candidate.

---

## Main Responsibilities

```text
- Receive input frame
- Receive reconstructed reference frame
- Receive PREI result
- Select intra mode candidate
- Generate Planar / DC / Angular intra prediction
- Compute predicted luma pixels
- Compute residual = original - predicted
- Estimate rate
- Compute cost
- Output intra prediction_result
```

---

## Main Input

```text
frame input
frame reconstructed
block region
prei_result prei_info
qp
```

Meaning:

```text
input          current frame
reconstructed  reconstructed reference frame
region         current block region
prei_info      intra mode candidates from PREI
qp             quantization parameter
```

---

## Main Output

```text
prediction_result
```

The output has:

```text
mode = prediction_mode::intra
```

The output contains:

```text
- valid flag
- intra prediction mode
- partition mode
- predicted_luma
- residual_luma
- distortion
- rate
- cost
- qp
```

---

## Main API

```cpp
prediction_result run(const frame& input,
                      const block& region) const;

prediction_result run(const frame& input,
                      const frame& reconstructed,
                      const block& region,
                      const prei_result& prei_info,
                      std::uint32_t qp = INIT_QP) const;
```

The first API is a compatibility API. It creates a simple internal PREI-like input and uses fallback intra modes.

The second API is the main POSI API. It uses the PREI result generated by the PREI block.

---

## Simplified Functional Flow

```text
Input frame + reconstructed frame + PREI result
      ↓
Collect candidate intra modes
      ↓
Generate Planar / DC / Angular prediction pixels
      ↓
Compute residual
      ↓
Compute distortion
      ↓
Estimate rate
      ↓
Compute cost
      ↓
Select best intra prediction result
      ↓
Generate prediction_result
```

---

## Intra Prediction Modes

POSI models simplified versions of HEVC intra prediction modes:

```text
- Planar mode
- DC mode
- Angular modes
```

The purpose is to generate a functional intra prediction result for mode decision or later pipeline stages.

---

## Relationship with PREI

```text
PREI
  ↓
prei_result
  ↓
POSI
  ↓
prediction_result with mode = intra
```

PREI searches or ranks intra modes.  
POSI uses those modes to generate actual predicted pixels and residuals.

## Test Description

Test file:

```text
posi/test/test_posi.cpp
```

The POSI unit test is a functional-level test for the POSI block. It verifies that POSI can consume PREI output, generate intra prediction pixels, compute residual values, estimate cost, and reject invalid input cases.

### Test Cases

#### 1. POSI from PREI on Gradient Frame

This test runs the normal intra dataflow:

```text
PREI → POSI
```

Test name:

```text
[TEST] POSI from PREI on gradient frame
```

Purpose:

```text
- Verify that PREI output can be consumed by POSI
- Verify POSI can process a non-uniform gradient frame
- Verify POSI generates a valid intra prediction_result
```

Main checks:

```text
- prei_info.valid == true
- result.valid == true
- result.mode == prediction_mode::intra
- result.qp matches the input QP
- predicted_luma size matches region area
- residual_luma size matches region area
- cost, rate and distortion are valid
- residual = original - predicted
```

#### 2. Flat Frame Zero Residual Test

This test creates a flat frame where all luma pixels have the same value.

Test name:

```text
[TEST] POSI flat frame should produce zero residual
```

Purpose:

```text
- Verify POSI behavior on a simple uniform block
- Verify predicted pixels are equal to the flat input value
- Verify residual becomes zero when prediction matches input
```

Main checks:

```text
- result.valid == true
- predicted_luma values are all 128
- residual_luma sum is 0
- distortion is 0
```

This is an important correctness test because a flat block should be predicted accurately by DC or Planar-like prediction.

#### 3. Manual DC Candidate Test

This test manually creates a PREI result with DC mode.

Test name:

```text
[TEST] POSI manual DC candidate
```

Purpose:

```text
- Verify that POSI can use a manually provided DC candidate
- Verify that POSI maps the candidate to intra_prediction_mode::dc
- Verify DC prediction on a flat frame
```

Main checks:

```text
- result.valid == true
- result.intra_mode == intra_prediction_mode::dc
- predicted_luma values are all equal to the flat input value
- residual_luma sum is 0
```

#### 4. Manual Angular Candidate Test

This test manually creates a PREI result with an angular mode candidate.

Test name:

```text
[TEST] POSI manual angular candidate
```

Purpose:

```text
- Verify that POSI can use a manually provided angular candidate
- Verify angular mode mapping
- Verify POSI can generate prediction pixels for angular mode
```

Main checks:

```text
- result.valid == true
- result.mode == prediction_mode::intra
- result.intra_mode == intra_prediction_mode::angular_26
- predicted_luma size matches region area
- residual_luma size matches region area
- residual = original - predicted
```

#### 5. Horizontal Edge Frame Test

This test creates a frame with a horizontal edge pattern.

Test name:

Purpose:

```text
- Verify POSI on directional edge-like image content
```

Main checks:

#### 13. Zero-Size Block Invalid Input Test

Test name:

#### 14. Out-of-Bound Block Invalid Input Test

This test passes a block that exceeds the frame boundary.

Test name:

```text
[TEST] POSI out-of-bound block invalid input
```

Example:



Expected behavior:


This test ensures that POSI does not silently accept block regions outside the input frame.

### Summary

The POSI test verifies:

```text
- PREI-to-POSI dataflow
- Gradient frame processing
- Flat frame zero-residual behavior
- Manual DC mode candidate
- Manual Angular mode candidate
- Horizontal edge input
- Vertical edge input
- Multiple block positions
- Multiple block sizes
- Compatibility API behavior
- Deterministic output
- Predicted luma size correctness
- Residual luma size correctness
- Residual = original - predicted
- Cost, rate and distortion field validity
- Invalid input handling
```

This is still a functional-level unit test. It does not prove bit-exact equivalence with RTL, but it provides stronger functional validation than a simple smoke test.

## Notes

POSI is currently modeled at functional level. It focuses on intra prediction behavior and does not model exact RTL timing, SRAM timing, or cycle-by-cycle control behavior.

The current test is designed for functional validation. Full RTL-equivalent verification would require comparison against RTL simulation results or a bit-exact golden reference model.
